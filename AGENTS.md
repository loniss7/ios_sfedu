# Инструкции для агента

## Контекст работы

Это Git-репозиторий с лабораторными работами по iOS/Swift. Основную часть работы пользователь выполняет на Windows в этой директории, отправляет изменения в свой удалённый репозиторий, а затем получает их командой `git pull` на учебном Mac, где открывает проект в Xcode, собирает приложение и показывает его преподавателю.

Поэтому результат работы должен быть пригоден для переноса через Git и открытия на другом компьютере. Считай Mac с Xcode конечной средой сборки и демонстрации. На Windows можно изучать и редактировать код, готовить ресурсы и проверять доступные платформенно-независимые части, но нельзя утверждать, что iOS-приложение собрано или проверено в Xcode, если фактически этого не происходило на Mac.

## Перед изменениями

- Уточни, какую лабораторную и какое задание меняешь. Работай только в относящейся к запросу папке; не исправляй и не форматируй соседние лабораторные без необходимости.
- Сначала прочитай README и все применимые `AGENTS.md` в целевой папке. Более близкие к файлу инструкции уточняют эти общие правила.
- Сохраняй существующую структуру и принятый в конкретной лабораторной стек. Не переноси код между Playground и iOS-приложением и не добавляй UI-фреймворки, зависимости или новые цели сборки без требования задания.
- Учитывай, что папки лабораторных могут содержать разные форматы: например, macOS Swift Playground и отдельные `.xcodeproj` для iOS. Проверяй назначение проекта по его README и настройкам, а не только по расширению Swift-файлов.

## Windows → Git → учебный Mac

- Все необходимые исходники, ресурсы, настройки Xcode-проекта, схемы и файлы разрешения зависимостей должны быть представлены в репозитории и пригодны для чистого checkout на Mac.
- Не добавляй в проект абсолютные пути Windows или Mac, настройки пользователя, локальные ключи и сертификаты подписи, содержимое `DerivedData`, продукты сборки и другие файлы, созданные только на одной машине. Не ослабляй `.gitignore` ради таких файлов.
- Для подключаемых ресурсов проверь, что они отслеживаются Git и ссылки на них используют правильное имя и регистр. Учитывай, что файловая система Mac может различать регистр имён файлов.
- Не рассчитывай на несохранённые локальные изменения, установленные только на Windows инструменты или файлы, отсутствующие в репозитории. Если приложению нужны пакеты или ресурсы, сохраняй необходимые manifests/настройки и укажи в README, что Mac должен получить или разрешить.
- Не меняй Git remote, ветки, историю и не выполняй push/commit от имени пользователя без отдельной просьбы. Оставляй изменения в рабочей директории, чтобы пользователь мог отправить их в свой репозиторий.
- Если для демонстрации требуется действие на Mac (открыть `.xcodeproj` или `.playground`, выбрать схему/симулятор, разрешить пакеты, настроить подпись), добавь точные короткие шаги в README соответствующей лабораторной. Не предполагай наличие конкретного симулятора, устройства, версии Xcode или Apple Developer-подписи, если это не указано.

## Техническая точность

- Не заявляй о сборке, запуске в симуляторе или прохождении проверок, если они не выполнялись. Если Xcode недоступен в текущей среде Windows, явно обозначь это в итоговом сообщении и перечисли нужные шаги на Mac.
- Не запускай тесты и не добавляй новые тесты, если пользователь этого не просил. Если запрос требует именно проверки, используй подходящий доступный инструмент; для iOS/Xcode-проверки укажи, что её нужно выполнить на Mac, когда Xcode недоступен.
- Сохраняй совместимость проекта с его целевой платформой и настройками. Не меняй deployment target, идентификатор приложения, схему, настройки подписи или структуру проекта без причины, связанной с заданием.
- Для новых или существенно изменённых лабораторных обновляй README: назначение, путь к проекту, как открыть и запустить его на учебном Mac, а также ограничения или известные шаги подготовки.
- В итоговом ответе кратко перечисли сделанные изменения, назови их пути относительно репозитория и отдели фактически выполненную проверку от шагов, которые ещё нужно выполнить на Mac.
